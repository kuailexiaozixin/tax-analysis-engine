# 深交所法律规则（szse-lawrules）目录检索

把深交所「法律规则」栏目按关键词建成**本地索引**，之后离线查询，命中给出
「规则名 + 发布日期 + 原文链接 + 所属分类」。母技能主线里，它补的是**交易所自律规则**
这一层——五个税收源、MaoDocs、chenyiwei-bbs 都不收证券交易场所自己的业务规则。

线上：http://www.szse.cn/www/lawrules/ （公开匿名可访，无需 token）

## 什么时候用 / 不用

**用**：问题落到证券交易所层面的规则——上市条件、发行上市审核、信息披露、交易与回购、
会员管理、异常交易监控等；或要点名某部门规章 / 规范性文件在交易所官网的原文与发布日期。

**不用**：税率、扣除、优惠期限这类纯税务规则（走主线五源）；会计/审计/内控/评估准则
原文走 `subskills/maodocs/`。**交易所自律规则不进 ⑧ 的税收效力位阶表打分**（证券监管
口径，与税法不同源），与 MaoDocs 一样只作专业口径与适用边界用。

## 站点渲染分两种（本机 2026-09-29 实测）

1. **标准库直连可枚举**（默认 `build` 覆盖）：法律 / 行政法规 / 司法解释 / 证监会规章 /
   适用指引 / 规范性文件 / 废止公告。这类页面把每条规则内联成
   `var curHref / var curTitle` + `<span class="time">`，翻页是 `index.html → index_1.html`，
   纯 urllib 即可枚举，实测 724 条。
2. **运行时模板，需浏览器**（`build --browser` 补）：十二类「本所业务规则」（股票/债券/
   基金/衍生品/REITs/会员/交易通则…）。页面只挂 `_.each(data,…)` 模板，直连返回空壳，
   要点真浏览器渲染出 `a.art-list-link` 锚点。这里复用母技能既有的
   `scripts/tax_browser.BrowserSession`（**不新增依赖**；playwright 缺失时该通道自动跳过并在回显写清）。

落地页 `lawrules/index.html` 还把「最新业务规则」约 122 条内联 SSR 出来，`build --snapshot`
把它们并入索引，作为交易所自律规则的快照（不需要浏览器）。

## 工作流

脚本在本目录 `szse.py`，四条命令，全部 stdout 出 JSON。索引落在 `szse_index.json`
（随技能分发不含，用前 `build` 一次即可）。

### 1) 列全部通道（别名 / 中文名 / 渲染类型）

```bash
python szse.py categories
```

### 2) 建索引

```bash
python szse.py build                 # 只建标准库通道（快、无浏览器）
python szse.py build --snapshot      # 再并入落地页最新规则快照
python szse.py build --browser       # 再补"本所业务规则"通道（需 playwright+浏览器）
python szse.py build --browser --channel stock   # 只补一个业务规则通道
```

回显 `total` 与逐通道条数；playwright 不可用时浏览器通道记 0 并写明原因，不影响其余。

### 3) 离线查询

```bash
python szse.py query 内幕交易
python szse.py query 回购 --channel snapshot --limit 10
```

返回按发布日期倒序的 `results[]`（title/date/url/channel/channel_cn）。

### 4) 取某一条正文

```bash
python szse.py fetch http://www.szse.cn/lawrules/rule/trade/current/t20260424_620190.html
```

HTML 详情页直连取正文；`.pdf/.doc` 附件只回链接与提示（正文需下载后另行解析）。

> **Git Bash 注意**：喂以 `/` 开头的相对路径会被 MSYS 改写；`fetch` 直接传完整 URL 最稳。

## 取到之后放哪（给母技能主线看）

同 MaoDocs：交易所规则**不是税收法定依据**，不进 ⑧ 位阶表打分。只占两处——
【适用边界】里当"本结论假定证券交易/信息披露层面按 X 处理"，或【执行口径与实务
认定】栏写
"规则名＋条款号"。引用只写"规则名＋（修订年份）"，**不把 CMS 文号或 URL 里的 t 编号当版本依据**。

## 两条硬规矩

- **URL 与文号都不证明版次**。实测 `…/t20250327_612564.html` 这条，标题写"（2023年修订）"、
  发布日期列 2023-12-15，URL 里的 t20250327 只是站方 CMS 生成序号。版次以正文措辞自证。
- **发布日期是站方录入项**，与"施行日""修订日"可能不同；答案要写生效时点时按正文自述，
  不拿列表日期顶替。本技能给的是**目录与定位**，不是时效判定。
