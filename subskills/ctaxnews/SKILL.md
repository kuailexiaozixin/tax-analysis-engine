# 中国税网（ctaxnews.com.cn）站点子技能

中国税网是中国税务报社的媒体站点，跑在方正建站系统上，内容页是静态服务端渲染，没有 WAF、
不校验 UA，也不返挑战页——这一站的取数难点不在凭据，而在**同一篇稿子被切成三套互不相通的编号**
与**参数取值越界不回错误码**这两条上：一篇稿挂几栏就有几枚 articleid，检索只按叶节点收而不按子树收，
2023 年 2 月改版前的行地址少一段目录、永久取不到正文。判据写在本文件，
逐项读数（含取样口径）记在 `NOTE.md`，复测靠 `probe_ctaxnews.py`。

## 工作流

**第一步 定这一趟要什么**——下面几行的入口、耗时与前置各不同，先选对再动手：

| 要什么 | 走哪条 | 前置 |
|---|---|---|
| 按关键词找文章，还要每行日期、栏目、文号、发文机关 | `tax_ctax.search_ctax(关键词)`，即 `GET /xy/Search.do` | 无：开放 JSON 接口，不要凭据、不启浏览器 |
| 在上面这一路上再限定栏目、发布日期区间、只匹配标题，或按总条数取全 | 同一函数的 `node`、`date_from` + `date_to`、`match`、`fetch_all` | 按栏目名限定时要 `data/ctax_columns.json` |
| 手上只有一枚文号，要回站内找税网登的那几篇 | `tax_ctax.find_by_doc_number(文号)`，命令行 `--find-doc` | 无 |
| 不检索，直接把某一栏列表页的清单读几页 | `tax_ctax.list_column(栏目, pages=N)`，命令行 `--list` | 栏目表（按名限定时） |
| 只读已知 URL 的正文与页面层元信息 | `tax_ctax.fetch_ctax` / `read_articles` | 无 |
| 这一栏的目录名、nodeID、整栏行数 | `load_columns()` 读 `data/ctax_columns.json` | 读表不发请求；重建（`--update-columns`）才发 |

界面那一路走不通，不必启浏览器：首页搜索框的 `onsubmit` 调用了一枚站点没有定义的
`per_submit`，点下去在请求发出之前就抛 `ReferenceError`；结果壳里那个排序下拉框整块写在
HTML 注释里，页面上没有能用的排序控件。可用的只有 `/xy/Search.do` 这一路。

**第二步 参数只按站点认的那一式提交**。取值域逐档实测过（读数见 `NOTE.md`
「Search.do 的参数值域」），越界的回法分两类：一类直接 HTTP 500——日期给毫秒时间戳或
斜杠分隔这种非 `yyyy-mm-dd` 形态，`sort` 给站点不认的值（站点收 `date`、`score` 与空串三档，
后两档是同一份换序结果；回 500 的是 `relevance` 与 `orderbypubtime`，后者正是壳里那个注释掉的
下拉框的取值），`_search_once` 在错误说明里写明"这一档的取值越界时报 500，不是限流"；
另一类**静默按缺省处理**，回一份看着成功其实没生效的数据，下面三处最费人：

1. 翻页只认 `pageNo`。`start`、`page`、`pageNum`、`p`、`offset`、`currentPage` 六枚别名站点一律忽略，
   提交它们等于反复取第一页。`pageNo` 从 0 与从 1 起都是第一页（`search_ctax` 从 1 起）。
2. `q` 会把位置参数盖掉。站点的匹配域靠"提交哪一枚参数名"表达（`q` 全文、`title` 只标题、
   `keyword` 只站点关键词字段、`author` 只 author 段），`q` 与 `title` 同时提交时 foundNum
   仍等于只给 `q` 的那一份——所以 `match` 的实现是换参数名，不是给 `q` 加限定。
   `q` 另一条要自己守住：**一个概念一枚词，多词之间没有可用的 AND 语义**——站点按整串字面匹配，
   同一批词正序「增值税 留抵退税」1,940、倒序 12、粘一枚库里没有的词回 0
   （`NOTE.md`「Search.do 的参数值域」那五行表）；与税屋那一路的判据相反，两边不能互相套用。
3. 一稿多发的行不合并就会占满额度。检索按栏出行，同一篇挂四栏出四行且 articleid 互不相同，
   `--size 5` 按行数收时实际只回两篇。`dedup_rows` 按「标题＋发布日期＋文号」三项同并成一条，
   合并掉的栏目名收进 `also_in_columns`；收满的判据也按并完的篇数算。

日期区间两枚各自独立，不必成对提交：只给起始或只给截止，站点照常按那一侧收
（同一枚「增值税」实测：只给起始 2,537 行、只给截止 45,739 行、成对取 2025 全年 1,405 行），
`search_ctax` 也只在参数有值时才提交那一枚。

**取值域在本层先判，判过才发**。`search_ctax` 交出「没走成」的六种写法都是零请求退出：
空词没限栏目、日期非 `yyyy-mm-dd`、`match` 不在 `MATCH_POSITIONS` 那四枚里、`channel` 不在
0/1/2 里、不收满时 `size` 不是正整数、`max_rows` 为负；`--list` 那一路再多一枚，`pages` 非正也不发。
两处拦停的理由不同：拼错的 `match` 过去会换成 `q` 发出去，取回的是全文那一摞，读数看着像
"标题限定生效了"；越界的 `channel` 过去会打到站点那份 37 字节空结构，那句与"这一词没命中"
长得一样。`--size` 收的是合并同稿后的**篇**数，`--max-rows` 收的是站点给的**行**数，
两枚都只收紧（取小的那一份），翻到底撞到行数上限时 `_status` 写「已到 max_rows=N 行的上限」，
不写"这一词只有这些"。

**第三步 栏目限定只认叶节点，查不到或有重名就整体报缺**。`nodeID` 给父节点回 0 条而它下面
确实挂着文章（政策那一族面包屑上的四层 24/672/8196/8210 空词各回 0，最末一层的 8215 回 23），
这一条写在 `_filter_note` 里，不静默当成"这一栏没有内容"。栏目名换算成 nodeID 只查
`data/ctax_columns.json`，`column_lookup` 交三种判据：`ok` 一个命中，`ambiguous` 两个以上行对上
（站点确实有重名栏目，本轮重建的表里「实务分析」「疑难解答」「申报指引」「税务行动」各两行），
`missing` 表里没有。后两种一律把请求停在发出之前，`_status` 以「没走成」开头并列出候选，
**不发一条半截限定的命令**——那看着像收窄了其实没有，重名时也不替读者挑一条。
`missing` 不等于站点没有这一栏：这张表只装首页导航与父栏目页各展开一层走得到的 79 栏，
表外的深层栏（672、8210、8215 是这样的）按名限定必然落空，知道编号就直接给 `--column 8215`，
编号只写在 `NOTE.md`「栏目表的重建读数」里。

**第四步 行里的地址先判可达性，再决定发不发请求**。`_address_state` 只看地址形状：
域名后不足四段路径的行取不到（回 HTTP 500；错误页尺寸随 `User-Agent` 变，带浏览器 UA 572 字节、
不带 UA 170 字节，所以字节数不是判据，见 `NOTE.md`），这类行是 2023-02 改版前的老行，
目录段猜不得（对同一行试原址、换协议、再补 `policy`/`news`/`sssw`/`sswfaj`/`zt`
五枚目录名，七路全回 500，见 `NOTE.md`）。段数是唯一判据，协议不进判断：这一批老行恰好
写成 `http://`，但换成 `https` 也一样取不到。
所以老行只当**题录**用：标题、发布日期、文号、发文机关都在检索行里，正文不在。
取不到时挂 `_url_state` 说明原因，不重试——这一站的错误地址回 500 而不是 404，
重试没有意义还占间隔。

**第五步 取正文，字段只从页面层取**。正文夹在 `<!--enpcontent-->` 与 `<!--/enpcontent-->` 里，
元信息夹在 `<!--enpproperty<字段>值</字段>-->` 里；这两对标记**有的页面写两遍（桌面版与移动版）、
有的只写一遍**，块数跟栏目和目录段都没有对应关系，只能逐页量（取样 7 篇：4 篇两遍且逐字节相同、
3 篇只有一块，探针第 6 项每次量）；写两遍的两块目前取样都逐字节相同，`fetch_ctax` 取第一份，
两份不一致时 `_note` 写明只取了第一份。
`_http_get` 在响应头没写 charset 时强制按 utf-8 解——这个站的文章页回 `Content-Type: text/html`
不带 charset，requests 默认按 ISO-8859-1 解，正文会静默变成 mojibake 而 HTTP 仍是 200。
检索行里的两枚摘要字段都不进抽取，只当定位线索：`enpcontent` 有值的 195/200 行长度只有 120
与 123 两档、其中 194 行以三个英文点收尾；`Abstract` 有值的 174/200 行长度 9 到 193 不等、
3 行带收尾截断标记。两者都是报社截出来的摘要，不是原文全文；要全文回页面取。
站点自己标的时效与税种线索只写在页面层：`liability`（效力标注）与 `tag`（分号分隔的税种标签），
`fetch_ctax` 交成 `liability` 与 `tags`。取样的 7 篇里只有 `policy` 目录段那两篇标了「全文有效」，
`sssw`、`csxw`、`zt`、`csll`、`sswfaj` 五篇两枚字段都是空串——**字段为空读成"站点没标"，
不读成"这篇没有依据"**，也不能反过来写成"政策页必有标注"（样本只有两篇）。
检索行里没有这两枚字段，别按行判时效。

**第六步 回母技能定级——但要自己认这一层是登载件，别等程序替你标**。
被它登载的那份文件才是法定依据（母技能 ⑦ 第 6 条），政策类转载要回官方站点核对原文。
`tax_evidence.rank_of` 的角色判据是**标题形态先、来源兜底**：转载件的标题就是原文件那份标题，
所以「财政部 税务总局公告2026年第29号」这类行会按形态判成 `normative`（`role_of` 给
`direct`，实测），而 `PRACTICE_SOURCES` 那六枚来源标记里没有 `ctaxnews.com.cn`，
标题不含"解读"二字的行也不进 `interpretation` 兜底，落 `unknown`、角色成 `unmatched`。
**两条都不意味着这一路可以当依据引**：定级读的是那份文件本身的位阶，不是这个地址的资质，
答案里的依据链要写官方库那份的 url，这一路的地址只作定位与线索。
`liability`（站点自标的效力标注）只作提醒，不接进时效判定。判据见母技能 ⑧ 与
`references/evidence_grading.md`，本子技能不参与。

## 命令

```bash
# 检索并按篇取正文
python scripts/tax_ctax.py "出口退税" --size 5 --read
python scripts/tax_ctax.py "研发费用加计扣除" --size 5 --json          # 只要链接与字段
python scripts/tax_ctax.py "增值税" --match title --size 20           # 只匹配标题
python scripts/tax_ctax.py "留抵退税" --column 政策解读 --size 10      # 限定一栏（名称或 nodeID）
python scripts/tax_ctax.py "增值税" --column 63 --from 2025-01-01 --to 2025-12-31
python scripts/tax_ctax.py "留抵退税" --all --max-rows 500            # 按 foundNum 翻页，先到 500 行收口
python scripts/tax_ctax.py --find-doc "财政部 税务总局公告2026年第29号"   # 按文号定位并合并同稿多栏
python scripts/tax_ctax.py --list 税案通报 --pages 2     # 不检索，按栏目列表页取清单（交回 0 行不等于这一栏没内容）
python scripts/tax_ctax.py --columns                                # 打印本地栏目表，不发请求
python scripts/tax_ctax.py --update-columns                         # 重建栏目表（逐栏目空词计数，声明 102 次＝当期一轮实发，随站点节点数与父栏目数浮动）
python subskills/ctaxnews/probe_ctaxnews.py                         # 全项复测（声明 209 次请求，第 6、7、8、10、12 项按站点当期读数浮动）
python subskills/ctaxnews/probe_ctaxnews.py --fast                  # 同上但不重建栏目表（107 次）
python subskills/ctaxnews/probe_ctaxnews.py --items 3,5 --keyword 留抵退税   # 只跑值域与栏目两档
```

命令行与函数同一份判据。`--channel 0` 在本层等于不提交这一枚，拿到的是网站与触屏的并集；
`--channel 3` 这类站点不认的值现在发不出去（`_status` 以「没走成」开头，零请求），
那一份 37 字节的空结构只在直接给 `_search_once` 传越界值时才拿得到——站点侧的这一档记在
`NOTE.md`，读的时候不要把它当成"这一词没命中"。

## 栏目表与整栏行数

`--update-columns` 从首页导航读 `node_<id>.html` 的链接，逐枚节点发一次空词检索取整栏行数与
行内栏目名，再把空词回 0 行的父栏目展开一层。栏目名有两个来源，优先级是实测出来的：
**行内 `nodesearchname` 是站点自己的叫法，拿得到就用它**；导航锚文本只作父栏目的退路，
且要压掉排版空格（首页写的是「政 策」），而 `nodesearchname` 里的空格保留
（「财政部 国家税务总局公告」中间那个空格就是站点写法）。子栏的名字不从父栏继承。
「更多 >>」（首页与栏目页上都有这种占位入口，写法带竖线或 more）按 `_is_nav_placeholder` 扣掉，
本轮重建发出 91 次探测、进表 79 个（其中 26 个父栏目），名字取不出或属占位链接的 12 个不进表，
命令行把这 12 枚节点的编号一并打到 stderr，免得读者把"表里只有 79 栏"读成"这个站只有 79 栏"。
空词检索的 foundNum 就是这一栏的总行数，这是"整栏有多少"的唯一入口——
栏目页每页交回的行数随模板浮动（14 份栏目页副本量出 0、10、15、18、25、100 六档），
翻页控件报的总页数也不固定（同一批里读到 10、7、3、2 四档，另有三页没有这枚控件），
两数相乘才是栏目页那一档能给的上限，且上限随模板变，所以整栏规模不靠翻栏目页得到。

## 栏目页这一档只回答"最新一段"

栏目列表页是 `/<目录>/node_<id>[_<页>].html`，翻页控件 `div.pagelist` 把总页数写在
`<ul pages='N' current='M'>` 的属性上。`N` 最大读到 10：税案通报一栏检索报 1,648 行，
栏目页第 11 页回 HTTP 500。栏目页每页交回几行随模板浮动（见上一节那六档），
所以 `--list` 只当"读这一栏最新一段"用，读到 0 行不等于这一栏没有内容——
要整栏清单回 `search_ctax(node=…)` 按 foundNum 翻。
取行**不认列表容器的类名**：站点实测出现的容器有三枚（`div.newsList-item`、`ul.onlyTitleList`、
`ul.ztNews-list-main`），14 份副本里 `a.hsqj-list` 与 `ul.tabList` 两处 0 命中，早先把它们
列为"五种形态"的两枚不算数；而 `newsList-item` 那一枚在页面上写成 `newsList-item clearfix`，
按精确类名匹配的话 14 页全读 0 行。`_page_rows` 因此按**地址形状**取行——每一行的地址一律写成
`/<目录>/<yyyy-mm>/<dd>/content_<id>.html`，发布日期就在这条路径里
（取样的 200 行检索样本里，路径日期与行内 `date` 逐字符相同 200/200）。
归属判据分两道：页面能切出本栏标题（`column-header-1`）时只在那一段里取行，
切不出时目录段也不足以定性，同一目录下的兄弟栏长得一样，就再拿本栏的检索集
（`_column_id_set`，一次空词 nodeID 检索）交一遍。走到"切不出"这一支的实测有三枚：
14 份栏目页副本里只有要闻落地页 node_13 一枚（页上 17 处行全属别栏，`/news` 目录下 0 行，
交回 0 行并把扣掉的 17 行写进 `_page_errors`），另两枚不在那一批副本里、按 `--list` 命令行回显记
（增值税 node_8030 与父栏目 node_24）——
实测增值税那一栏的页面铺出 12 行，检索集里只有 4 行，多出的 8 行是同一目录下的兄弟栏；
父栏目 node_24 更极端：页上 132 处行里 109 处目录段是 policy，而这一栏自己检索 foundNum 0，
交集后交回 0 行。**父栏目页不是"只铺子栏入口"**，它铺的是别的栏的行，
而 `nodeID` 又不按子树收（第三步），所以整栏清单只走叶节点那一路。
同一篇的配图链接与标题链接同址，按地址并成一行；并完仍没有文字的行丢掉，不编造标题。

## 边界：这一层不给什么

1. **不给法定依据**：税网是报社的媒体站点，它登载的那份文件才是依据（母技能 ⑦ 第 6 条）。
   注意这一条程序不会替你把关：`rank_of` 按标题形态把转载件判成原文件的位阶，
   `PRACTICE_SOURCES` 里也没有这一站，所以答案里的依据链要自己写官方那份的 url。
2. **不给地方规定的原文替代**：省局原文在母技能 ③ L3 那一路，税网的地方税收法规栏是转载与解读，
   引地方规定仍要回官方站点核对原文。
3. **不给整站全量**：栏目页最读到 10 页、每页行数随模板浮动（0 到 100 行都实测出现过），
   整栏清单只能靠空词检索的 foundNum 那一路；检索取全的上限是 `SEARCH_MAX_PAGES` 页 ×
   `SEARCH_PAGE_SIZE` 行，给了 `--max-rows` 时先到那一枚行数就收口。两种都只在 `_status`
   写明取了多少行、总条数是多少与撞到的是哪一枚上限，不把"取到的这一段"读成"这一词只有这些"。
4. **不给 2023-02 之前的正文**：那一年的行地址缺栏目目录段，取不到（取样 2,617 行里 1,834 行如此）。
   题录字段仍可取，正文回官方库或后来的转载件。
5. **不给触屏端**：`channel=2` 那一路空词只有 18 行，16 行挂「总局微信内容」、2 行挂「测试栏目」，
   日期跨 2018-07-06 至 2019-10-10，且行内地址全是缺目录段的三段老形态，取不到正文，
   所以 `CHANNEL_WEB` 是默认值。省略 `channel` 是两端并集，同一枚词的 foundNum 会多出触屏端那几行：
   「增值税」多 18 行（46,889 对 46,871），「出口退税」多 4 行（9,804 对 9,800），
   多几行随词变，别按固定值估。
6. **不给时效结论**：`liability` 与 `tag` 只站点自己标，标没标、多久更新没跟官方库对过，
   接进判据就把"站点没标"读成"这份还有效"；空值也只是没标。
7. **不给"文号没对上就是引错"的结论**：实务材料里的文号回官方库逐条核对
   （`tax_answer.check_practice_citations`，结果挂 `official_status`）；
   `not_in_library` 读成"我们查的那份库里没对上"。
8. **不并发加压**：`READ_INTERVAL = 1.0` 秒与 `SEARCH_MIN_GAP = 1.0` 秒是礼节性间隔——
   实测零间隔连发 14 次检索加 10 篇正文全回 200，站点没表现出限流；这两枚常量写在这里
   是为了让复跑能对上，不是站点要求的额度。
9. **不越站点自己的声明**：`robots.txt` 在这个站回 HTTP 500，站点没有声明可爬范围，
   因此按只取公开内容页与检索接口、不并发、不解附件执行。
