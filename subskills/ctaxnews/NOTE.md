## Search.do 的参数值域

取样集：站内检索的 4 枚词（增值税、留抵退税、出口退税、财政部 税务总局公告2026年第29号）与
空词全站；抽取形态：逐次只改一枚参数，读回 HTTP 状态、响应字节、JSON 的 `foundNum`、
`article` 长度与首行 `articleid`；比对规则：与"只改这一枚参数前"的 `foundNum` 与首行编号比。
首行编号必须一起取——排序类参数换序时 `foundNum` 一动不动，只比总数会把"站点收了这个值"
读成"这一档没生效"。探针第 2、3 项复跑这一张表。

| 参数 | 站点认的取值 | 越界的回法 |
|---|---|---|
| `pageNo` | 只认这一枚翻页参数；`0` 与 `1` 都是第一页（站点自己的 JS 从 0 起，本层从 1 起） | `start`、`page`、`pageNum`、`p`、`offset`、`currentPage` 六枚别名一律静默忽略，提交等于反复取第一页 |
| `pageSize` | 到 5,000 都照数给行（nodeID=63 一轮回 1,393 行 = 该栏全部） | 无报错；本层默认 50，取全时不放大到 5,000 而是按页翻 |
| `sort` | `date` 按发布日期倒序；`score` 站点也收（同一词 foundNum 不变、首行换成另一枚编号：基准 1123977 → 985745）；空串与 `score` 是同一档（`pageSize=50` 下两份都回 56,166 字节、首行同为 985745，而 `date` 基准回 47,185 字节） | 回 HTTP 500 的两枚：陌生值 `relevance`（228 字节）与 `orderbypubtime`（233 字节）——后者正是结果壳里那个被注释掉的排序下拉框的第二枚取值，界面上写着"按发布时间排序"而后端不收；本层只提交 `date`，不接换序那一路 |
| `siteID` | 只有 `2`（网站）出结果 | `1`、`3` 回空结构，不报错 |
| `channel` | `1` 网站、`2` 触屏端；省略 = 两端并集 | `0`、`3`、`20`、`-1` 四枚各发一次，回的逐字节是同一份 37 字节空结构，站点不报参数错；**这一条最容易被读成"这一词没命中"** |
| `startDate` / `endDate` | 只认 `yyyy-mm-dd`；**单给一侧也生效**（「增值税」只给 `startDate=2025-01-01` → 2,537、只给 `endDate=2025-12-31` → 45,739、成对 2025 全年 → 1,405，基准 46,871）；与 `nodeID` 同发时两样都在收，日期没被静默换成整栏（node_63 不带日期 1,393 行，加 2024 全年回 46、加 2016~2019 回 0） | 毫秒时间戳（244 字节）、`yyyy/mm/dd`（241 字节）都回 HTTP 500；起止倒挂不报错，`foundNum` 直接 0。探针第 3 项复跑日期档、第 5 项复跑栏目加日期那两发 |
| `nodeID` | 只认**叶节点**，且不按子树收 | 面包屑链上的五层同日各发一次空词检索：政策(24)、法规专题(672)、2026年重要财税法规合集(8196)、2026年（税种）(8210) 四枚都回 `foundNum=0`、零行，只有最末一层的 其他税种(8215) 回 23 条——0 不是那一层没有文章，是检索不替它往下收，链是从 `content_1123898.html` 的面包屑上读的，五层里只有 8215 带行。`--update-columns` 那 91 次探测走过的 11 页（首页 + 10 枚父栏目页）里，672、8210、8215 三枚一次都没出现，所以栏目表里没有它们；8196 有行，但它不挂在 `node_24.html` 那 20 枚编号里，是 `node_8015` 那一页带出来的（见「栏目表的重建读数」）。结论：按名限定只能限定到表里那 79 栏，表外的栏要限定就得直接给 nodeID |
| 位置参数 | `q`（全文）、`title`、`content`（正文，比 `q` 窄）、`keyword`、`author` 五枚，各只认单独提交 | `q` 与 `title` 同发时 `foundNum` 仍等于只给 `q` 的那一份——`q` 盖掉位置参数，所以"只匹配标题"必须只发 `title=` |
| `paperID` | 站点收这一枚，且当收窄条件用：`paperID=1` 与 `paperID=999` 各发一次都回 HTTP 200 加 37 字节空结构（`foundNum=0`），而不是回忽略它之后的 47,185 字节基准 | 有效的那一枚编号这一层给不出：结果壳的 `Set-Cookie` 把 `xy_search_paperID` 恒写 0，首页 HTML 里「paper」字样 0 处（没有版面页入口可反推编号），站点也没有给出可枚举的版面清单。本层不接这一枚。探针第 3 项复跑两档回法、第 12 项复跑那两处首页计数 |

五枚位置参数的同一枚词计数。取样口径：`pageNo=1`、`pageSize=50`（计数读 `foundNum`，与
页大小无关）、`sort=date`、`siteID=2`，只改提交哪一枚参数名；`channel` 那一列写"省略"的
一格都没提交这一枚（两端并集），写 `1` 的一格显式提交网站端。两列不同数不是噪声而是并集：

| 词 | `channel` | `q` | `title` | `content` | `keyword` | `author` |
|---|---|---|---|---|---|---|
| 增值税 | 省略（两端并集） | 46,889 | 11,911 | 46,516 | 908 | 0 |
| 增值税 | `1`（网站） | 46,871 | 11,909 | 46,498 | 908 | 0 |
| 出口退税 | 省略（两端并集） | 9,804 | 1,752 | 9,746 | 65 | 0 |
| 出口退税 | `1`（网站） | 9,800 | 1,752 | 9,742 | 65 | 0 |

两列之差就是触屏端（`channel=2`）里命中这一档的行数：「增值税」在 `q` 与 `content` 上各差 18
（等于触屏端那一档的 18 行，见「触屏端与整站规模」），`title` 差 2（18 行里 2 行标题带这一枚词），
`keyword` 与 `author` 差 0；「出口退税」`q` 与 `content` 各差 4，其余三枚差 0。

`content` 严格小于 `q`（同一词、同一端各差 373 行：网站端 46,871 对 46,498、并集 46,889 对 46,516），
站点没说明 `q` 比 `content` 多匹配了哪一段；
本层 `match=content` 走的是 `q=`，这一档差异记在这里，不当成同一件事。
`author=增值税` 回 0 行，而检索行里 `author` 有值的 20/200 行装的是成文日期串
（见下节），这一段能提交、但站点自己的数据没往里放正文词。

`q` 按整串字面匹配，分词与多词语义都得按实测说话。基准那一发加四发正控（同一轮、口径同上表）：

| 提交 | `foundNum` | 排除掉哪一种解释 |
|---|---|---|
| `q=增值税` | 46,871 | 基准 |
| `q=留抵退税` | 3,409 | 单发第二枚词的基准：交集不可能比它大 |
| `q=增值税zzz不存在的检索词zzz` | 0 | 按词取并——并集不可能回 0 |
| `q=增值税 留抵退税`（空格分隔，正序） | 1,940 | 第一枚没参与收窄——1,940 严格小于 3,409 |
| `q=留抵退税 增值税`（倒序） | 12 | 顺序无关的按词交集——同一批词换个顺序得出另一个数 |

两枚真词换顺序得到不同的数，而粘一枚库里没有的词回 0：既不是按词取并，也不是顺序无关的按词取交，
只有"这一整串按字面参与匹配"能同时解释这两档。所以 `SKILL.md` 第二步第 2 条写的是
**一个概念一枚词，多词之间没有可用的 AND 语义**（与税屋那一路的判据相反，两边不能互相套用）。
探针第 4 项把这四发连着期望语一起复跑：粘词不回 0、或正序与倒序同数，这一条就要改。

## 检索行的字段与值域

取样集：「增值税」`channel=1` 首页 200 行（`foundNum` 46,871）；抽取形态：`article` 数组原样；
比对规则：按 `sorted(row.keys())` 归一并数形态。

`siteid`、`nodesearchname`、`sourcename`、`Abstract`、`channel`、`url`、`urlpad`。
**行里没有 `nodeid`、没有标签、没有效力标注**，栏目只能读 `nodesearchname` 那一枚行内名字。

## 老地址的可达性分界

取样集：2,617 行 = 空词整栏取回的 2,417 行（nodeID=63 全部 1,393 行 + 60/61/62/64 那一簇 1,024 行，
`pageSize=5000` 一次取回）+「增值税」检索行 200 行；抽取形态：`url` 与 `urlpad` 原样；
比对规则：按 `url` 去掉域名后的路径段数分档，再逐档取 `date` 边界；
被比的库：无（这一段只看站内地址形状，不比外部库）。

  补上的那一段救不回正文——所以触屏端这一路只用来数条数，不接进取正文（探针第 13 项复跑这五发）。
  省略 `channel` 时「增值税」46,889 = 网站 46,871 + 触屏 18。
- `channel` 的越界值取 `0`、`3`、`20`、`-1` 四枚各发一次：其余参数固定为「增值税」、`pageNo=1`、
  `pageSize=50`、`sort=date`、`siteID=2`，走域名那一路落点。四份响应逐字节相同，都是 HTTP 200 加
  37 字节的 `{"start":0,"foundNum":0,"article":[]}`，站点不报参数错。站点侧只登记 `1` 与 `2` 两枚，
  本层另把 `0` 用作"不提交这一枚"，这三枚之外的值一律不发请求。探针第 3 项复跑这四枚。
- 真没命中回的是同一串：`channel=1`、其余参数同上，把 `q` 换成库里确实没有的词
  （「zzz不存在的检索词zzz」）也是 37 字节的 `{"start":0,"foundNum":0,"article":[]}`。
  返回值里分不出"`channel` 这一枚写错了"和"这一词没有结果"，判据只能放在发出去之前。

## 限流与延迟

取样集：14 次检索（含 5 次 `pageSize=5000` 的整栏取回）+ 10 篇正文，零间隔连发；
抽取形态：HTTP 码与响应字节数；比对规则：看有没有 429、挑战页或体积骤减的行。
全部 200，没有限流表现。所以 `READ_INTERVAL = 1.0` 与 `SEARCH_MIN_GAP = 1.0` 是礼节性间隔，
不是站点逼出来的下限——写进代码是为了让复跑能对上，别当"站点只给这个速度"。
本轮审计复跑 137 次，回 500 的 14 次全是故意取的：第 13 项那两轮的 10 发老地址与 `urlpad`
（每轮 5 发），加第 8 项四轮里各带的那一发 `node_23_11.html`（栏目页第 11 页，翻页上限那档的读数）；
其余 123 次全 200，也没出现 429 或体积骤减的行。第 8 项四轮里有一轮整项报错，
但 15 发请求照发、回码与正常那轮一样，按实发计。
之后补的那 127 次（见开头「取证请求数」）没有落到"取不到"那一档：重建那一步回显
「发出 91 次探测、取回 91 个节点」，10 枚父栏目页逐页交出了编号，临时脚本的检索与页面取回也都正常返回。
单轮耗时：`--fast` 一轮 107 次请求、每次 1 秒间隔，两三分钟上下；全项一轮 209 次。
第 10 项（栏目表重建）声明的 102 次就是 2026-10-19 那一轮的实发：首页 1 次、逐节点空词探测 91 次、
父栏目页各一次 10 次。三档各由站点当期决定：探测次数等于首页导航与各父栏目页捞到的节点数，
取页次数等于其中空词回 0 行、又拿得到目录段的那几枚；`update_columns` 只把探测那一路封在
`max_nodes=120` 内，取页那一路不另封，所以换一轮建站点的父栏目数就换实发——两头都可能差。
命令行把探测/取回/进表/没进表四档计数打到 stderr，实发数不靠猜。

## 探针项与请求数

`probe_ctaxnews.py` 的每一项都只读发货代码里的判据（`tax_ctax` 的
`SEARCH_ENDPOINTS`、`_search_once`、`_row_from_json`、`dedup_rows`、`_address_state`、
`_page_rows`、`_own_region`、`_column_id_set`、`fetch_ctax`、`column_lookup`、`update_columns`），
不另立一份判据。唯一的例外是第 12 项要比"站点自己的提交法与本层的是不是同一份字节"，
