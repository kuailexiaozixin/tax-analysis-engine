# 研发费用加计扣除与高企认定合规分析（rd-deduction-hitech）

研发费用税务合规的**专项分析子技能**：高企认定算分、研发费用加计扣除归集测算、
口径隔离与协同（会计／高企／加计三套口径的科目级基准，另有 R&D 统计与 IPO 披露两套
扩展口径）、2026 监管与稽查应对，并可产出内控制度/流程/表单模板与
加计/高企/IPO 三套资料包草稿。

## 什么时候用 / 不用

**用**：

- **评分类**：申报高企前自评——"我们能过高企吗""还差多少分""先补哪一项最划算"。
- **归集与测算类**：加计扣除六类费用归集、10% 限额测算、委托研发 80%/境外 2/3、负面清单判定。
- **口径与协同类**：同一笔研发支出在会计核算／高企认定／加计扣除三套口径下能不能归集、
  限额怎么算、R&D 统计与 IPO 披露两套扩展口径的差异、双优惠叠加、重复归集风险。
- **监管与稽查类**：2026 监管新动向、单季研发占比核查、稽查应对、资格维持与撤销后果。
- **制度与资料类**：研发费用内控制度、日常管理规范、表单与审批矩阵、加计/高企/IPO 三套资料包草稿。

**不用**：

- 需要登录税务机关/科技部门系统操作（在线申报、汇算填报、合同登记）——本技能不代办。
- 专项审计、鉴证、法律尽调、辩护——需执业资质，本技能不替代。
- 纯税务政策条文检索与依据定级——走母技能主线（五个税收源 + ⑧ 定级与依据分层）。
- 单一窄问题（"这笔支出该资本化吗"）可直接答，但保持与合规分析视角衔接。

## 三条能力线

### ① 高企认定评分自检

规则见 `references/hitech-scoring.md`（八条一票否决 K1–K8 + 四项指标 30/30/20/20、
71 分达标）。流程：**采集决定性字段（一次只问一个关键项）→ 按规则核算 → 输出评分报告**。

- 决定性字段：注册年限、技术领域、最近一年销售收入、近三年研发费用占比、科技人员占比、
  高新收入占比、核心知识产权数量。
- 输出硬规则：一票否决在前；每项失分给原因；补齐路径按性价比排序并标难度；
  成长性不可补；未提供数据单列；不承诺通过。
- 合规红线：不承诺通过、不代编申报材料、不替代专项审计、不虚增费用、提示当地口径。

### ② 研发费用加计扣除归集与测算

规则见 `references/deduction-guide.md` 与 `references/rd-mgmt-methodology.md`
（第 2 章研发活动界定 / 第 4 章归集流程 / 第 5 章加计 6 项费用与委托研发）。

- 比例：一般企业 100%（2023 年第 7 号）；集成电路/工业母机 120% 至 2027-12-31；
  预缴 7 月/10 月/汇算三次（2023 年第 11 号）。
- 六类费用：人员人工 / 直接投入 / 折旧 / 无形资产摊销 / 新产品设计费等 / 其他相关费用（10% 限额）。
- 限额公式：`限额 =（可加计总额 − 其他相关费用）× 10% ÷ (1 − 10%)`，超限部分不得加计。
- 委托研发：按实际发生额 80% 计入；境外部分不超过境内符合条件的研发费用 2/3。
- 负面清单行业主营且收入占比 >50% 不得加计。

### ③ 口径隔离与协同、2026 监管与稽查应对

规则见 `references/rd-mgmt-methodology.md` 第 4.1 节（科目级口径基准）与
`references/audit-response.md`（监管与稽查）：

- 三套口径的科目级取值以 `references/rd-mgmt-methodology.md` 第 4.1 节为唯一基准：加计与高企都是
  正列举、会计不是；房屋折旧与长期待摊只有高企口径能归集；其他费用上限高企 20%、加计 10%；
  委托研发两口都按 80% 计入，加计另受境外不超境内 2/3 约束；冲减只发生在加计口径。
  对外任何口径结论都要写明适用口径与年度，不得由一套口径推出另一套。
- 2026 监管：抽查率 16.52%、实质穿透式审核、单季研发占比偏低无说明可暂停 15% 优惠及加计申报资格、穿透式电子台账核验。
- 稽查重点与公开案例（陕西永明虚列研发 / 西藏慧业人员造假 / 南氏锂电归集混用）及整改路径。
- 资格维持（年报、更名重组 3 个月报备）与撤销后果（追缴+滞纳金、5 年内不得再申请）。

## 数据来源（无系统数据库）

本技能**不连接任何业务系统、不读写数据库**。所有数字来自：

1. 用户明确提供的数据（金额、比例、台账、合同、凭证）；
2. 用户上传的资料文件；
3. 公开政策文件（`references/policy-docs/` 等）。

缺失即标「（待补）」并提示补录，绝不虚构；没有真实费用数据时不得给出
"未超出限额"等合规结论。

## 工作流

1. **识别诉求**：评分 / 归集测算 / 口径协同 / 稽查合规 / 制度资料 → 按上表加载对应参考文件。
2. **采集数据**：向用户逐项采集（一次只问一个关键项），比例填小数、金额以元为单位；
   缺什么列"待补资料清单"。
3. **核算**：先按 `rd-mgmt-methodology.md` 第 4.1 节定这笔支出在各口径的取值与限额公式，
   再按 `hitech-scoring.md` 算分、按 `deduction-guide.md` 算基数；
   可借助母技能脚本做本地计算（无模型调用）。
4. **产出**：
   - 评分 → 评分自检报告（一票否决在前、评分明细、补齐路径、免责）。
   - 归集 → 归集表 + 10% 限额测算 + 辅助账（模板 `templates/03-forms/forms.md` 表单 8）。
   - 制度 → 基于 `templates/01-regulations/`、`02-processes/` 模板生成制度/流程/规范草稿。
   - 资料包 → 按 `workflow-evidence.md` 生成加计/高企/IPO 三套资料包草稿 + 证据清单。
5. **交付**：Word/PDF/Markdown；交付形态与归档建议随文给出，证据链整理为台账 + PDF 归档。

## 红线（不可突破）

1. **不编数据**：金额、占比必须来自用户提供资料或公开政策文件；缺失列待补。
2. **不承诺通过**：高企评分只说"自评得分"与"不达标项"，不承诺认定/下证结果。
3. **政策必须引用**：涉及加计/高企/IPO 判定，引用 `regulatory-basis.md` 对应法规条款；
   引用政策前检查 `policy-updates-2024-2026.md` 时效性。
4. **不代办申报**：不代填申报系统、不代提交材料；专项审计/鉴证由资质中介机构出具。
5. **不虚增费用**：补齐路径只能指向真实的制度建设、真实的知识产权申请与真实成果转化。
6. **不替代专业服务**：产出为草案/自评，重大税务、法律结论须提示专业复核。
7. **跨口径不得外推**：一笔支出在会计、高企、加计三套口径下的结论各自独立，只对相关口径下结论。
   不得写"会计已计入研发费用，因此可以加计/可以高企归集"；逐科目差异与出处见
   `references/rd-mgmt-methodology.md` 第 4.1 节。
