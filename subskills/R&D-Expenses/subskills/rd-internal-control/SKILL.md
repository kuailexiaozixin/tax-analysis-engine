# 内控建设与流程优化（rd-internal-control）

> 属「R&D Expenses」技能族。**通用 SOP**——总则（尤其"实质合规 · 制度先行"）、六步工作流、交付要求、交付前自检——见 [`../../SKILL.md`](../../SKILL.md)。本文件只写**本任务的特有环节**。
> 知识底座：[`../../policy/`](../../policy/README.md)、[`../../cases/`](../../cases/README.md)。

## 边界

- 本技能管**制度、流程、内控、文档体系**的建设与优化（事前）。
- 本技能是总则第一条"**实质合规 · 制度先行**"的落地主战场：财税合规的前提是真实的研发活动与完善的研发管理。
- **风险排查** → [`../rd-risk-diagnosis/SKILL.md`](../rd-risk-diagnosis/SKILL.md)；**被查应对后的制度修补** ← [`../rd-audit-response/SKILL.md`](../rd-audit-response/SKILL.md)。

## 典型问法

- 研发管理制度怎么写？
- 研发项目立项要留哪些痕？怎么杜绝"先研发后补立项"？
- 工时管理、领料管理怎么做才经得起查？
- 研发内控体系怎么搭建？
- 研发 / 财务 / 税务 / 人事怎么分工协同？

## 需收集信息清单

| 类别 | 需收集 |
|:---|:---|
| 现有制度 | 研发管理制度、流程文件清单 |
| 关键环节现状 | 立项、实施、结题、工时、领料、产出、文档管理现状 |
| 跨部门职责 | 研发 / 财务 / 税务 / 人事的分工与协同现状 |
| 记录与台账 | 工时记录、领料记录、辅助账、台账现状 |
| 痛点与目标 | 现存问题、改进目标、是否需配套模板 |

## 专属 SOP（在通用六步之上）

1. **现状诊断**：盘点现有制度、流程、记录与缺口（立项有没有？工时有没有？领料与产出去向有没有？文档留存够不够？）。
2. **制度框架设计**：立项（技术 + 财务 + 税务三审）→ 实施 → 结题 → 工时管理 → 领料与产出管理 → 文档 / 辅助账管理。
3. **流程与职责**：明确研发 / 财务 / 税务 / 人事的跨部门联动与职责边界，做到"数据能互相印证"。
4. **落地模板**：制度文本、流程图、表单与台账模板。
5. （可选）与 `rd-risk-diagnosis` 联动做"制度体检"，闭环整改。

## 交付物

- 研发管理制度文件
- 流程图与职责说明
- 表单 / 台账模板

## 内置模板库（29 份，可交付）

本技能内置 **29 份可交付模板**（制度 16 / 流程 7 / 表单与报表 6），文件使用 `{{占位符}}`，填入企业信息即成稿；清单与用法见 [`templates-index.md`](templates-index.md)。

- **制度**（`templates/01-regulations/`）：内控、立项、验收、档案、预算、加计申报管理、工时、人员、绩效、物料、设备、模具、样品、成果、产学研/专利、差旅会议。
- **流程**（`templates/02-processes/`）：研发流程节点、日常管理规范、加计申报 6 阶段、费用报销、人员认定、设备共用分摊/外部核查、预算调整与跨期。
- **表单/报表**（`templates/03-forms/`）：基础表单 8 + 补充表单 10 + 报表 4（加计归集/加计测算/高企占比/IPO 核查）+ 三套证据清单 + 人工分配表 + 口径差异说明。
- 方法底座：[`references/rd-mgmt-methodology.md`](references/rd-mgmt-methodology.md)、[`references/regulatory-basis.md`](references/regulatory-basis.md)、[`references/workflow-governance.md`](references/workflow-governance.md)、[`references/workflow-evidence.md`](references/workflow-evidence.md)。
