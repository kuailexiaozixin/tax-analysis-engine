# 依据定级：位阶与时效

> 本文件是 `SKILL.md` ⑧ 的下沉版。核心一句话：**引用任何法条之前必须先判定它是否有
> 效；可引用性 = 位阶 × 时效系数，低于 50 分只能当参考。** 判据落在
> `tax_evidence.grade` / `pick_primary` / `judge_validity` / `rank_of`。

## 位阶分值表

五个源返回的东西不是一个量级的凭据。混在一起当"依据"贴进答案，读者分不清
哪句能拿去和税务机关据理力争、哪句只是行业参考。

| 位阶 | 分值 | 判定依据 |
|-----|-----|---------|
| 宪法 | 100 | 标题以"中华人民共和国宪法"开头 |
| 法律 | 90 | 全国人大及其常委会决定，"…法"结尾 |
| 行政法规 | 80 | 国务院的条例、暂行条例、实施条例 |
| 部门规章 | 70 | 部委以令发布的办法、规程、实施细则 |
| 规范性文件 | 55 | 总局/财政部等的公告、通知、批复 |
| 地方性法规 | 50 | 省级政府条例、办法、规定 |
| 地方规范性文件 | 40 | 省/市税务局文件 |
| 技术性口径 | 25 | 解读、答问、政策指引、操作指南 |
| 实务解读 | 10 | 税屋文章、公众号推文 |

可引用性 = 位阶 × 时效系数。系数：现行有效 1.0、时效未标明 0.78、
尚未生效 0.7、已废止 0.35。**低于 50 分（`tax_evidence.PRIMARY_THRESHOLD`）
只能当参考材料。**

表外的一栏：企业会计准则条文与会计准则实务答疑（子技能取回的那一层）根本不在这张
表里，也不打分。它答的是"会计上怎么确认与计量"，是税法适用的前提而不是税法的规定，
所以既不占依据层也不占参考层的分数——位置见 `out_of_library_layers.md`。

## 依据线为什么卡在 50

这道线卡在 50 而不是更高的位置，是因为要挡的是"以什么身份引用"，不是"文件等级"：

- 总局公告、财税通知这类**规范性文件（55 分）是税务机关据以执法、纳税人据以办理
  的直接依据**，把 60 分当线会把它们成片归进"只能参考"，等于让答案避开真正落地的
  那层规则——而这正是 L2 下挖要取的东西。
- 折减自动把它们在时效不明时请回参考层：规范性文件 × 未标明 = 42.9、× 尚未生效
  = 38.5、× 已废止 = 19.3，都低于 50。**"现行有效"才配得上"依据"这个身份**。
- 仍在参考层的：技术性口径 25、实务解读 10、地方税务局文件 40、未定性 30。
  条目自带 `_reliability: medium/low` 时分数已被清成 0，不会从这道线漏进来。

## rank_of 判定顺序

`tax_evidence.rank_of` 判定的先后顺序，决定了几个容易判错的形态：

1. **标题以「解读」收尾 → 技术性口径**，先于分类与形态规则判。解读件的标题里
   整份嵌着被解读文件的原名（"国家税务总局关于……的公告的解读"），按分类字段
   或按文件名形态都会把它认成那份公告本身，把一份技术性口径当规范性文件引出去。
2. **来源给的效力级别字段优先**（NPC 的 `flxz`、总局的 `effect_level`，如
   "税务规范性文件"）。有这一项时按它归档，比按标题后缀猜准；只有字段缺失才走
   形态规则。
3. **形态规则的中间段要容得下书名号**。公告标题常写成"国家税务总局关于发布
   《企业重组业务企业所得税管理办法》的公告"，中间整段嵌着被发布文件的书名号。
   规则若用"汉字类"匹配中间段就会断在 `《` 上，整条判成未定性（30 分），一份
   现行有效的规范性文件被压到只能参考。程序改用了"除句号以外任意字符"的中间段
   （`tax_evidence._RANK_RULES` 里的 `[^。]`），并在注释里写明了这个原因。

**位阶低于 60 不等于不能当主依据**：用户点名某一份规范性文件时，那一条就是答案
的对象，程序把它放主依据并要求与并列的上位法同读，见 `out_of_library_layers.md`
与 SKILL.md ③ 的"用户点名了某一份文件"。

## 时效判定七条

对每一条准备引用的条文，依次确认：

1. **现行有效**（NPC `status=3`；总局条目看录入项 `xxgk_aging`，如"全文有效"）
   — 可作主依据
2. **尚未生效** — 只能用于说明即将发生的变化，不能支撑当期结论
3. **已废止** — 只能用于说明政策沿革，且必须在答案里标注"已失效"
4. **已修改 / 已修订** — 法规库把这一档与"废止/全文失效"分开发：标了已修改的
   仍然在效，只是文本被改过。程序按现行有效计分，同时在判定理由里追加"文本已被
   修改，引用须按修改后的版本"，这句要写进答案。
5. **时效未标明** — 按 0.78 折减；若这是唯一依据，要写明"未标明施行日期，
   引用前请核对最新公告"。NPC 的 `sxx` 字段本身可能为空，此时输出里
   `status_code` 是 `null`、`status` 是 `未知(None)`，不能当成"现行有效"读；
   界面对应显示"时效未标注"徽章
6. **状态说"尚未生效"、但没给施行日期** — 传了 `--at` 也仍判 `pending`。
   时点判定要靠施行日期证明它已经在效，"没查到日期"推不出"日期一定在过去"。
   早先的实现把这一格倒向 `effective`，等于用推荐用法（带 `--at`）把一份还没
   开始施行的公告顶成主依据；现在只有施行日期不晚于观察时点才转正（`tax_evidence.judge_validity`）。
7. **本栏根本不录时效** — 总局法规库的「财税文件」栏没有时效录入项（实测财税〔2009〕59
   号、财税〔2014〕109 号该栏为空，财税〔2003〕16 号那个位置是字符串 `null`），详情页
   也只有成文日期。这类文件按状态字段只能报"时效未标明"，会被压在依据线以下。程序改
   用**制定依据援引**补这一格：点名文件的正文首段"根据《……》（财税〔2009〕59号）等
   文件规定"把它列为制定依据，而该点名文件自己现行有效，据此判在效（`tax_answer.corroborate_validity_from_target`
   → `corroborated_by` → `tax_evidence.judge_validity`）。答案里必须照抄 `validity_note`
   那句证据来源，并保留"引用前按该文自身的时效复核"这一层；明文废止或未生效的文件不会被
   这条翻案。

总局条目的时效来自录入项时，`status_from` 会写明是哪一个录入项给的；答案里的
时效结论要能追溯到这一句，不要改口成"据标题推断"。

观察时点必须显式传入：同一问题在 2023 年和 2026 年答案可能不同。

```bash
python scripts/tax_evidence.py --rank "国家税务总局公告2018年第28号" --at 2026-09-27
```

`tax_answer.py --answer` 会自动完成定级并输出：主依据（位阶最高且时效可用）、
并列依据（现行有效的法定文件，含总局公告这类规范性文件）、只能参考的、
已废止的、尚未生效的，以及该写明的限制条件。并列依据与只能参考两栏打印时有截断，
截掉的条数会写成"…另有 N 条未列出"，答案里要按这个数说明还有多少同类文件，
不能把截断后的清单当成全部。
