# 依据定级：层级、时效、角色与提醒

> 本文件是 `SKILL.md` ⑧ 的下沉版。核心一句话：**引用任何法条之前必须先判定它在观察
> 时点是否仍在效；规范层级只用来在同角色的两条之间裁决先后，不折算成"能不能引用"的
> 分数。** 判据落在 `tax_evidence.grade` / `rank_of` / `judge_validity` / `on_topic_of`
> / `role_of` / `pick_primary`，实务材料援引的文号另有一道回库核对，落在
> `tax_answer.check_practice_citations` 与 `tax_evidence.OFFICIAL_CAVEAT`。

## 三根轴加一档角色

一条材料身上有三件互相独立的性质，加上一档"它在这道题里干什么活"。它们各自有各自的
判据函数，任何一件都不许折算成另一件：

| 性质 | 判什么 | 判据 | 带不带"不能用"的后果 |
|-----|-------|-----|---------------------|
| 规范层级 | 谁不得抵触谁 | `rank_of` → `LEGAL_RANK` | 不带。只用于同角色冲突裁决 |
| 时效 | 观察时点上还在不在效 | `judge_validity` | **唯一带后果的一根** |
| 与本题的对应关系 | 标题或正文里有没有本题的主题词 | `on_topic_of` → True / False / None | 不带。换成一句提醒 |
| 角色 | 这条在答案里顶哪一层 | `role_of` | 决定它能不能当主依据 |

三根轴不能乘成一个数，理由见下一节。

表外的一栏：企业会计准则条文与会计准则实务答疑（子技能取回的那一层）三根轴都套不上。
它答的是"会计上怎么确认与计量"，是税法适用的前提而不是税法的规定，所以既不参与层级
比较也不进时效判定——位置见 `out_of_library_layers.md`。

## 三根轴为什么不能乘成一个分数

把三根轴乘成一个数——`可引用性 = 位阶 × 时效系数`，低于某条线整条压成"只能参考"，
来源存疑（`_reliability: low`）时把分清成 0 并整组不许挑主依据——会同时犯三个独立
的错，每一个都能单独把答案做错：

1. **乘法把"谁不服谁"和"该引哪一条"混成一件事。** 宪法位阶 100、现行有效系数 1.0，
   按公式是全场最高分、会被挑成主依据；而我国法律实践中宪法不得直接作为执行依据。
   反方向同样错：问"六税两费减免怎么享受"，答案在一份总局公告里，规范性文件那一档
   配任何小于 1 的时效系数都容易被压到线以下。
2. **一根线把整层材料划到依据之外。** 给技术性口径与实务解读配上低于规范性文件的
   分数，意味着税屋与公众号的全部产出永远进不了依据栏。这否定了这一层的价值：法条要
   落到实践中才有价值，光分析法条与真实税务操作的差距很大。正确的处置是仔细甄别、
   严谨分析、给出可落地建议并做必要提醒，不是给它标一个低位阶然后忽略。
3. **降权代替了核对。** "可引用性 30 分""⚪ 仅参考"这种标签没有告诉读者疑在哪一处、
   要动手核对什么，读者只能选择整条忽略或整条照抄。同样的信息写成一句话的
   提醒（`caveats`），材料照常参与分层。这一层配的是真正的核对动作：实务材料
   援引的文号回官方库查存在与时效，见「实务材料援引的文号回库核对」。

`grade()` 的输出里**没有 `score` 字段**，`tax_evidence` 里也没有
`authority_score` / `PRIMARY_THRESHOLD` / `RELIABILITY_BLOCK` 这三个符号。留一个
分数字段就会被下游重新拿去排队，所以连字段名都不设；`tests/test_source_defects.py`
的 `TestNoSynthesisedCitationScore` 会扫源码守住这一条。

## 规范层级表

`LEGAL_RANK` 只装《立法法》确立的那几档，分值是**序号**不是权重：

| 层级 | 序号 | 判定依据 |
|-----|-----|---------|
| 宪法 | 100 | 标题以"中华人民共和国宪法"开头 |
| 法律 | 90 | 全国人大及其常委会决定，"…法"结尾 |
| 行政法规 | 80 | 国务院的条例、暂行条例、实施条例 |
| 部门规章 | 70 | 部委以令发布的办法、规程、实施细则 |
| 规范性文件 | 55 | 总局/财政部等的公告、通知、批复、函、意见、决定 |
| 地方性法规 | 50 | 省级政府条例、办法、规定 |
| 地方规范性文件 | 40 | 省/市税务局文件 |

技术性口径（`technical`）与实务解读（`interpretation`）**不在这张表里**——它们是材料
形态不是规范层级，`_tier()` 对表外取值一律返回 0，程序不给它们编一个假序号。这两档
合起来叫实务层（`PRACTICE_RANKS`），来源命中 `PRACTICE_SOURCES`（税屋、微信公众号、
搜狗微信）或标题含"解读"时也归到这里。它们与法定文件之间不比大小，只分担不同的角色。

序号只在一个场景里被用到：同一角色、时效都判得出来的两条之间，取层级高的那条
（`_order_key` 的第四项）。层级高只意味着下位不得抵触它，不意味着它更适合回答某个
具体问题。

## 角色分层与主依据挑选

`role_of(rank, validity, topic_hit)` 按下面的顺序判，顺序本身就是判据：

1. 已废止 → `history` 政策沿革。时效是唯一带处置的轴，废止件只用于说明沿革。
2. 形态属实务层（`technical` / `interpretation`）→ `practice` 执行口径与实务认定。
   先看形态再看主题：一份"……的解读"即使标题里全是本题的词，它仍是被解读文件的
   说明件，不能顶替被解读那份文件当依据。
3. 主题词命中 → `direct` 本题的直接规定。
4. 层级未判出且主题也没命中 → `unmatched` 待核对线索。给一份来历不明的材料封
   "上位依据"，等于替它担保它没有的层级关系。
5. 其余（层级已知、主题未命中）→ `superior` 上位依据与授权。

`pick_primary` 的挑选规则：

- 唯一出局的是立法过程件（人大网草案、审议与征求意见公告，`legislative_process`）——
  它不是已公布的条文。这是事实层面的处置，不是降权；这些行仍然出现在
  `_runners_up` 与【待核对线索】里。
- 其余按 `_order_key` 降序：**是否可直接援引** → 角色 → 时效判得出来与否 → 规范层级
  序号 → 主题命中。`_reliability` 不在键里。
- 排序键由 `pick_primary` 与 `grade_all` 共用一个 `_order_key`。两处各写一遍迟早
  分叉，分叉之后"列表里第一位"和"挑出来的主依据"就不是同一条，答案会自相矛盾。

答一道具体题的标准配置是 `direct` + `superior` + `practice` 三层都有货，缺哪层就在
答案里写明缺哪层。`tax_answer.compose` 按角色分栏输出：【主依据】【其余法定依据】
（`direct`/`superior`）、【执行口径与实务认定】（`practice`）、【待核对线索】
（`unmatched`）、【已废止，仅可用于说明沿革】、【尚未生效】。

## 宪法不得直接援引

`NOT_DIRECTLY_QUOTABLE = ("constitution",)`，配套 `CONSTITUTION_NOTE` 一句提醒。约束
落在**排序键的第一位**：宪法仍然在分层里出现（上位依据那一层本来就该
有它），但永远不占头条。一组里只有宪法时仍然挑它，`_why` 会写明"本组里没有可直接
援引的法定文件，头条只能给宪法——它对税务机关不构成征税依据，答案要补一轮检索落到
具体法律条文"。这一句不是免责装饰，是下一步动作的指令。

## 案例材料不占位次

`scripts/tax_cases.py` 收回来的是"同一件事官方被查过没有、按什么口径处理过"，它不是
依据，是**支持层**：不进 `LEGAL_RANK` 的任何一档，不进 `grade()`，也不参与
`pick_primary` 的排队。台账里那两根轴与本页的三根轴各自独立，一条都不许混用：

| 轴 | 量什么 | 取值与判据 |
|---|-------|-----------|
| 规范层级（本页） | 谁不得抵触谁 | `tax_evidence.LEGAL_RANK` 七档 |
| 来源等级（类案层） | 这一条是谁发的 | `tax_cases.source_grade` → A1 税务总局本级 / A2 各地税务机关 / C 不是税务机关 |
| 材料层级（类案层） | 这一条是个什么东西 | `tax_cases.LEVEL_BY_SUBTYPE` → C2 官方公布的典型案例 / C4 报道或转载；C1 与 C3（判决、决定文书）只由税屋那一路按标题形态给，正文待核 |

来源等级与材料层级是两根正交的轴：同一条通报可以是 A2（省局发的）又是 C2（官方
公布的典型案例）；一篇 `[央视新闻]` 前缀的站内转载是 C 级来源、C4 材料，它不因为
挂在总局栏目下就变成官方口径。判它是哪种材料看的是子栏目代号（`SUBTYPES`：
c102025 查处通报、c102439 曝光典型、c102435 违法公布），认不出代号的落
「其他新闻」继续参与排序而不是删掉——删掉就等于把"我没认出来"写成"官方没公布过"。

来源等级只有两处可查（`tax_cases.issuer_of`：`publisher` 栏，没有就取标题冒号前那
一段），三档的判据因此是三步：署名带媒体字形（`MEDIA_PUBLISHER_RE`，收「中国税务报」
这一类名字里带"税务"的报纸）或标题带转载前缀 → C；署名带机关字形（`ORG_NAME_RE` 只认
完整机关名，比如总局本级的「国家税务总局」与带行政区划的地方局名，不认"署名里带
税务两字就算"），再按有没有行政区划（`ADMIN_MARK_RE`）分 A1 与 A2；两处都读不出发布方，只有落在官方案例栏目
（`CASE_SUBTYPE_NAMES`）才按栏目名义算 A1，其余一律 C。这一档不设默认值是 2026-10-04
实跑改出来的：当时「人民日报：研发费用加计扣除申报方式优化」和无署名的案情条目都
拿到了 A2，而 A2 说的是"各地税务机关通报"——读不出发布方不等于有机关背书。
每行的「核验状态」（`tax_cases.verify_note`）跟着这四种情形各给一句：官方栏目原文／
发布方是媒体／读不出发布方／子栏目未识别，前两种给的动作不同，不能并成一句"待核"。

三条跟着台账走的硬约束：

1. **旧案结论要按目标年度重验**。`REMAP_NOTE` 那一句随每条候选输出：案例的处理结论
   按其发生时的政策作出，能类比的是事实认定与证据评价，不是法律结论。政策变了，
   别人补缴的数额不能拿来当本题的算式。
2. **强度上限是"官方处理口径"，不是"司法裁判口径"**。本通道只覆盖税务总局站内的
   查处通报与曝光典型，法院判决与复议决定不在内（`LIMITATIONS` 逐条列出，随输出
   一起给）。答案里不得据这一层说"法院也是这么判的"。
3. **零结果也是结果**。没留下候选时台账照样给出检索轮次、查询列表、覆盖源、排除
   理由与局限，答案那一栏写"本轮没查到官方处理过的同类案件"，不写成"没有先例"。

## 提醒清单

`caveats` 是一个有序句子清单，顺序按"越靠近这道题的结论越先看"：能不能引 → 时效 →
与本题对不对得上 → 它援引的官方文件现在还算不算数 → 来源可靠性。每一句都要落到一个
可执行的动作上。

| 触发条件 | 提醒内容 |
|---------|---------|
| 层级属 `NOT_DIRECTLY_QUOTABLE` | `CONSTITUTION_NOTE`：不构成征税依据，要落到具体法律条文 |
| 时效为 repealed / pending / unknown | `VALIDITY_CAVEAT[时效]`：说明沿革要写原施行期间 / 不能答当期 / 引用前单独核对是否还在效 |
| `judge_validity` 返回 `qualified: True` | 把 `validity_note` 原句进提醒：佐证在效、文本已修改、部分条款失效、生效日晚于时点、无施行日期佐证、正文自载的执行期限已过、正文自载的执行期限尚未开始 |
| `on_topic` 为 False | 标题与正文里都没有本题的主题词，这条按字面召回，引用前先确认它规定的是不是这件事 |
| `on_topic` 为 None | 没传主题词，这条与题目的对应关系未经核对 |
| 条上有 `official_status` | `OFFICIAL_CAVEAT[结果]`：九种结果各一句，见「实务材料援引的文号回库核对」 |
| 带 `_reliability` 标记 | 提醒就是来源自带的 `_reliability_note` 原句；来源没写原因时才退成 `RELIABILITY_CAVEAT[档位]` 那句中性的话 |

档位相同的两条，提醒必须各说各的原因。`medium` 在本仓库有三个出处：NPC 正文检索
按全文分词命中、总局法规库第 2 页起排序变松、立法过程件不在五个源的收录范围内。
按档位配一句固定话（"这一条来自清单靠后的页位"）只有法规库那处对得上，另两处
拿到的是假提醒——全文分词与站内检索都没有"页位"这件事。所以这句
说明必须由来源自己写（`tax_fgk.FGK_DEEP_NOTE`、`tax_search.RELIABILITY_NOTES`、
`tax_answer._legis_round`），定级层与界面、命令行摘要都只照抄，不另存一份。

【⑦ 第 16 条正文】**禁止忽略 `_reliability` 标记带来的提醒**：提醒用来源随条目带下来的那句
`_reliability_note`（写明存疑在哪一处、要核对什么），答案照抄那一句；来源没写原因
时才用 `tax_evidence.RELIABILITY_CAVEAT` 那句中性的话。不许按档位自己编一句原因——
同一个 `medium` 在三个来源说的是三件事。标记不改变这条材料出现在哪一栏，也不参与
挑选，不得拿它当降权的理由。

`qualified` 这个标志存在的理由：`validity_note` 有时只是交代"这个结论来自哪一个录入
项"（比如"生效日 2026-01-01 不晚于观察时点"），那是判据来源的交代，占一条提醒会让
读者以为还有事没核完。只有真有待核对事项时 `qualified` 才为 True。

`citation_hint` 是一句话摘要：角色 + 层级 + 时效 + 首要提醒，没有提醒时写"按现行
有效条文引用"。

## 实务材料援引的文号回库核对

税屋与公众号的文章不是降权对象，它是"怎么落地"那一段的取材处；它真正的问题是口径
悬空——讲的规则可能早已废止。所以这里不打分、不排除，而是把它援引的文号拿回税务总局
法规库查存在与时效：`tax_answer.check_practice_citations` 逐条标注，结果写在条目的
`official_status`，句子在 `tax_evidence.OFFICIAL_CAVEAT`，经 `_caveats` 进这一条的
提醒清单。命令行 `--no-citation-check` 关掉这一层（每次答案省掉至多 4 次检索）。

【⑦ 第 17 条正文】**禁止把实务解读当成被解读文件的原文**：引用时必须标注它解读的是哪一份、原文是否
取到；只取到解读时要写明原文待核。

核对要发真实检索，所以有额度：每份答案最多核对 `OFFICIAL_LOOKUP_LIMIT`（4）个文号，
同一文号只查一次。`citation_note` 把进行到什么程度说成一句整体话——核对了几份、
几份因上限没查、九种结果各几条；逐条的下一步动作仍在该条自己的提醒行里。

| `official_status.outcome` | 这一条的意思 | 提醒给出的下一步 |
|---|---|---|
| `effective` | 库里查到这一份，观察时点在效 | 按它引用（文件名取库里的规范名） |
| `repealed` | 库里查到，已判废止 | 这篇讲的是不再执行的规则，按现行文件重取口径 |
| `pending` | 库里查到，尚未生效 | 答当期规则不能引它 |
| `unknown` | 库里查到，时效判不出 | 引用前单独核对它现在是否还在效 |
| `not_in_library` | 检索发了，取回的清单里没有一份文号与它相同 | 提醒带上用的哪个检索词和接口给的命中数；文号可能抄错、写法不同或不在收录范围 |
| `no_citation` | 读了正文，里面没写任何文号 | 这一篇没交代口径出处 |
| `no_body` | 这一轮只取回标题或摘要（跑了 `--no-body`） | 去掉 `--no-body` 重跑一遍；没读过正文不能写成"文章没标文号" |
| `not_checked` | 单次上限用满，这一条没发请求 | 是本轮没查，不是查无此件，单独回库确认 |
| `lookup_failed` | 那一轮没连上库，或接口给了命中数却没给清单 | 不能把"查不到"读成"库里没有"，补一轮再定 |

后四行是这一层的全部难度所在：**"没有"有三种，读者的动作各不相同**。接口挂了要补
一轮；有命中但对不上要怀疑文号；零命中要怀疑检索词的写法。三种都写成同一句"查不到"
的话，读者会拿错的那个动作去核对自己没错的那件事。区分靠的是来源自己打的标记：
`tax_fgk.search_fgk` 零命中时也会写一句 `_error` 当说明，故障才有 `_fetch_failed`，
接口没给清单才有 `_empty_reason`——认标记不认句子，是本层与 ⑤ 那条"取数失败不许
写成 0 条"共用的判据。

检索词要补前缀。`tax_terms.doc_numbers` 交回的是短形（"2023年第19号"），实测
`search_fgk` 拿短形零命中，而"国家税务总局公告2021年第5号"这种带机关的写法能精确
命中一份。`_citation_phrase` 就从文号左侧的原文里补出发文机关与文件类型，但**只认
`_ISSUER_TOKENS` 里的机关名当起点**：喂进去的是标题与正文拼起来的一整段，按字符
宽度从右截会把"减征车辆购置税的执行口径 依据"一起当成检索词，那种词一个也命中不了，
于是"现行有效"被写成"库里没对上"——假结论还带一句看起来有据的说明。认不到机关名就
照用裸文号，宁可命中宽，不猜前缀。文号本身按允许空格的形态定位（正文里常排成
"2021 年第 5 号"，而抽取器交回的是去过空格的短形）。

**已知的不足（实测）**：文章写成"《财政部税务总局关于……的公告》(2022年第15号"时，
文号左侧紧挨的是括号，补不出机关前缀，只能拿裸短形去查。这种情况报 `not_in_library`，
并把检索词与"有 2 条命中"一起写进提醒——它没有把这件事说成"库里没有这份文件"。要
收掉这一格得再按文件名对一遍，本层还没做。

认不出来的结果名不会静默变成空提醒：`official_caveat` 把结果名原样报出来，因为空串
在这一层的含义是"这条没核对过"。`test_nine_outcomes_are_all_reachable_and_each_has_a_sentence`
逐场景把九种结果都跑出来，并要求 `OFFICIAL_CAVEAT` 与 `OFFICIAL_OUTCOME_LABEL` 同键；
`test_every_outcome_literal_in_the_producer_has_a_caveat` 不跑代码，只扫
`check_practice_citations` 里写进字典值的小写英文字面量，逐个要求在两张表里有条目。

## rank_of 判定顺序

`tax_evidence.rank_of` 判定的先后顺序，决定了几个容易判错的形态：

1. **标题以「解读」收尾 → 技术性口径**，先于分类与形态规则判。解读件的标题里
   整份嵌着被解读文件的原名（"国家税务总局关于……的公告的解读"），按分类字段
   或按文件名形态都会把它认成那份公告本身，把一份技术性口径当规范性文件引出去。
2. **来源给的效力级别字段优先**（NPC 的 `flxz`、总局的 `effect_level`，如
   "税务规范性文件"）。有这一项时按它归档，比按标题后缀猜准；只有字段缺失才走
   形态规则。
3. **形态规则的中间段要容得下书名号**。公告标题常写成"国家税务总局关于发布
   《企业重组业务企业所得税管理办法》的公告"，中间整段嵌着被发布文件的书名号。
   规则若用"汉字类"匹配中间段就会断在 `《` 上，整条判成未定性，一份现行有效的
   规范性文件连层级都拿不到，角色也跟着掉到待核对线索。程序改用了"除句号以外
   任意字符"的中间段（`tax_evidence._RANK_RULES` 里的 `[^。]`），并在注释里写明
   了这个原因。
4. **形态与来源都不匹配才落 `unknown`**。未定性不扣分，它只意味着层级这一维判不了；
   角色那一步会去看主题词。

主题对得上但层级未判出的那份稿子仍然是"本题的直接规定"，层级判不了这件事由
`rank_by`（"标题形态与来源都不足以定级"）与提醒说清，不用压低角色来代替。

**实务层材料可以进论证**：用户点名某一份规范性文件时，那一条就是答案的对象，程序
把它放主依据并要求与并列的上位法同读，见 `out_of_library_layers.md` 与 SKILL.md ③
的"用户点名了某一份文件"。

## 时效判定八条

【⑦ 第 7 条正文】**禁止用未生效或已废止的依据答当期问题**：观察时点必须显式传入，
已废止依据只能用于说明沿革。

对每一条准备引用的条文，依次确认：

1. **现行有效**（NPC `status=3`；总局条目看录入项 `xxgk_aging`，如"全文有效"）
   — 可作主依据
2. **尚未生效** — 只能用于说明即将发生的变化，不能支撑当期结论
3. **已废止** — 只能用于说明政策沿革，且必须在答案里标注"已失效"
4. **已修改 / 已修订** — 法规库把这一档与"废止/全文失效"分开发：标了已修改的
   仍然在效，只是文本被改过。程序按现行有效判，同时把"文本已被修改，引用须按修改后
   的版本"作为一条提醒（`qualified: True`），这句要写进答案。
5. **时效未标明** — 单独核对它现在是否还在效；若这是唯一依据，要写明"未标明施行
   日期，引用前请核对最新公告"。NPC 的 `sxx` 字段本身可能为空，此时输出里
   `status_code` 是 `null`、`status` 是 `未知(None)`，不能当成"现行有效"读；
   界面对应显示"时效未标注"徽章
6. **状态说"尚未生效"、但没给施行日期** — 传了 `--at` 也仍判 `pending`。
   时点判定要靠施行日期证明它已经在效，"没查到日期"推不出"日期一定在过去"。
   把这一格倒向 `effective` 等于用推荐用法（带 `--at`）把一份还没
   开始施行的公告顶成主依据；只有施行日期不晚于观察时点才转正（`tax_evidence.judge_validity`）。
7. **本栏根本不录时效** — 总局法规库的「财税文件」栏没有时效录入项（实测财税〔2009〕59
   号、财税〔2014〕109 号该栏为空，财税〔2003〕16 号那个位置是字符串 `null`），详情页
   也只有成文日期。这类文件按状态字段只能报"时效未标明"。程序改用**制定依据援引**补
   这一格：点名文件的正文首段"根据《……》（财税〔2009〕59号）等文件规定"把它列为制定
   依据，而该点名文件自己现行有效，据此判在效（`tax_answer.corroborate_validity_from_target`
   → `corroborated_by` → `tax_evidence.judge_validity`）。答案里必须照抄 `validity_note`
   那句证据来源，并保留"引用前按该文自身的时效复核"这一层；明文废止或未生效的文件不会被
   这条翻案。
8. **状态字段说在效（或干脆没录），正文里却自载了一段执行期限** — 财税公告普遍写明
   期限（"自2023年1月1日至2027年12月31日""延续执行至2027年12月31日"），而清单层读不出
   日期：减免税目录的`有效`栏实测 912 条"有效期起/止"全空，法规库的时效栏对财税文件
   根本不录（第 7 条）——实测 2022年第30号与2026年第22号的清单条目，`status`、
   `effective_date`、`expiry_date` 三栏全是空值，只有`date`/`publish_date`有日期。
   期限在**正文层**取得到——实测 20 条带正文的法规库条目里 11 条含这两类句式；按
   `docType=财政部税务总局公告` 取 30 条正文再数，8 条写成"自X至Y"的成对区间、
   0 条出现两组以上。`tax_evidence.expiry_of` 取止日、`period_start_of` 取起日：止日
   先读录入项 `expiry_date`（目前五个源都不产出这一项，留作显式入口），再从正文抠——
   只认带引导词的写法（执行至、延长至、延续至、延至、期限至、有效期截至、有效期至）
   和明确的"自…至…"区间；裸"截至"不算，实测真实正文里"截至2021年9月30日成立满一年的
   企业"那个日期是统计基准日；引导词后面不是具体日子也不算（2022年第14号"留抵退税申请
   时间，延长至每月最后一个工作日"）；月份或日期不落在合法取值内的直接弃。**正文出现
   两个以上不同止期时返回空串**——一份公告可以把几项政策各自延到不同日期，替用户挑一个
   是猜。起日只认成对区间：单独的"延续执行至2027年12月31日"交代了止期、配不出起日，
   反过来判它"还没开始"是无中生有；两组以上区间时两端都弃（这一手在 30 条实测样本里
   0 条命中，由组装文本钉住，不是从真实正文里观察到的形态）。
   **两端都要与观察时点比过才算数，只比止期会出错判。**财政部 税务总局公告2022年第30号
   （公布 2022-09-30，正文"自2022年10月1日至2023年12月31日"）与2026年第22号（公布
   2026-07-27，正文"自2026年9月1日至2027年8月31日"）都是公布日早于自己的起日。
   只比止期就会让这两份在 `--at 2022-09-30`、`--at 2026-08-20` 拿到"观察时点在期内"
   那句错话。两端都含当日：止日等于观察时点当天仍在期内，起日等于当天即已开始，差一天
   才换位。
   越界时 `judge_validity` **保留原判**（`effective`／`unknown` 都不动），只给一条
   `qualified: True` 的提醒：止日已过问"先查这段期限之后有没有延续文件，没有延续不得按
   当期口径引用"，起日未到问"这段规定在观察时点还没开始执行，当期结论不得按它给，要另找
   观察时点当时适用的文件"。既不判 `repealed` 也不判 `pending`：剩下的两种可能——后续
   公告延续了同一政策、这段止期本属正文引用的另一轮期限——从这一条材料里都判不了，压档
   会把可能仍在使用的主依据整条丢掉。两端都盖住观察时点时只把止日附在 `validity_note`
   末尾，不另占一条提醒（没有别的待核对事项时 `qualified` 为 False），答案要写"这项优惠
   执行至某年某月某日"时从这里取。录入项给得出施行日期时以它为准、正文那句不再参与起日
   判断：两处不一致是数据冲突，而"生效日晚于观察时点"那一格本来就按录入项判。
   这一支的先后次序有两处讲究：施行日期晚于观察时点时"尚未生效"先判（还没开始施行的
   文件谈不上"这段期限已过"或"还没开始"）；第 7 条的制定依据援引也先判——援引说的是这份
   文件整体还在效，止期说的是正文里那一段期限，后者不能把前者顶掉，否则带正文的财税文件
   一被抠出止期就从"佐证在效"掉回"时效未标明"。
   **摘要层不得接入这条抽取**（2026-10-04 实测：检索「增值税」带 `docType=财政部税务总局公告`
   取前 25 条，把清单摘要与详情页正文各喂一遍 `expiry_of`／`period_start_of` 对照；摘要取
   接口的 `content` 栏，25 条全非空、平均 124 字，另一栏 `shortContent` 平均 291 字）。
   对照结果分两头看。一是覆盖：正文层抠得出期限的 13 条、摘要层 6 条，其中 7 条是"正文给得出、
   摘要给不出"——摘要那句常在写到日期之前就截断。二是**有 1 条两端不一致，且摘要那句更"完整"**：
   财政部 税务总局公告2022年第15号（对增值税小规模纳税人免征增值税，法规库 c5202026）正文只有
   214 字，里面有两处止期——第一条规定的优惠"执行期限延长至2022年3月31日"、本公告"自2022年
   4月1日至2022年12月31日"，`expiry_of` 按"两个以上止期返回空串"弃掉、`period_start_of` 给出
   2022-04-01；摘要那栏从"适用3%征收率的应税销售收入，免征增值税"起头，没带上"延长至2022年
   3月31日"那半句，止期集合因此只剩一个，于是抽出完整一对 2022-04-01 至 2022-12-31。
   照摘要抽就等于把正文里另一处止期当不存在。按现状这里没有活缺陷：期限抽取的输入被
   `tax_evidence._body_of` 限定在 `content` 与 `body` 两处，清单
   摘要不在其中（实务层那一路的文号回库核对 `tax_answer.check_practice_citations` 读
   摘要，抽的是文号不是日期）。记这一条是把"顺手把摘要也喂进抽取"这个将来会犯的错先挡住。

**这一支怎么被证伪过**：`tests/test_judge_validity.py` 里 `TestSelfStatedExpiry`（16 条）
与 `TestSelfStatedPeriodStart`（14 条）合起来 30 条用例（该文件共 41 条），对 12 处变异
逐个跑——去掉录入项施行日期优先、起日分支整体停用、两组区间仍取起日、期限提醒抢在
"尚未生效"之前、两端各差一天（止日含当日判成已过 / 起日当天判成未到）、在期内那句漏记
当天、在期内那句不看止日、`dated` 扩到废止与未生效档、提醒句丢掉判据来源、提醒只判不说、
早返回恒假——**12 处全部打红**。"在期内那句不看止日"这一处的失效路径是：状态栏空、
录入项施行日期又晚于观察时点时，"执行期限已过"那条提醒被"尚未生效"让位，一路走到末尾的
常规交代档，只因为抠到了止日就在句尾附"观察时点在期内"，同一条 note 里会同时出现施行
日期未到与期限已过两句反话（`test_in_period_claim_never_says_past_expiry` 锁这一格）。

`note_extra` 里**不写** `not (start and start > at)` 这一句比较：
1008 格组合（六种状态 × 三种施行日期 × 有无援引 × 四种正文 × 七个观察时点）逐格比对
有无这一句的输出，差异 0 条——起日晚于观察时点时 `period_core` 必非空，而它三个消费点
都排在 `note_extra` 前面，这句永远轮不到被读，加回来也不改变任何输出。

总局条目的时效来自录入项时，`status_from` 会写明是哪一个录入项给的；答案里的
时效结论要能追溯到这一句，不要改口成"据标题推断"。

观察时点必须显式传入：同一问题在 2023 年和 2026 年答案可能不同。

```bash
python scripts/tax_evidence.py --rank "国家税务总局公告2018年第28号" \
  --at 2026-09-27 --topic 企业重组
```

命令行会打印层级、时效与它的判据、角色与主题对应、来源可靠性、是否不可直接援引、
逐条提醒，以及一句话引用建议。

**收口判据**：`tax_answer.compose` 看的是本轮有没有取到至少一条角色为 `direct` 或
`superior` 且未废止的法定文件。没有时输出 `evidence_gap`——各栏里只剩执行口径、
立法过程线索或已废止件——转 `output_templates.md`「依据不足时」形态，不给数额性结论。
注意这一闸与"五源全空"是两种不同的空手：五源全空是没搜到东西，这里是搜到了却没有
一条规定了这件事。实务层（`practice`）再多也不能满足这一闸，因为它按形态就不是已
公布的条文；这是角色分工，不是对它的贬低。

`tax_answer.py --answer` 会自动完成定级并按角色分栏输出。各栏打印时有截断，截掉的
条数会写成"…另有 N 条未列出"，答案里要按这个数说明还有多少同类文件，不能把截断后的
清单当成全部。
