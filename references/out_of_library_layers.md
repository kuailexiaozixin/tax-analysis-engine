## 用户点名了某一份文件

**用户点名了某一份文件**（"解读《关于……的公告》（2026年第13号）"这类问法）时，
在分轮检索之前先按标题把这一份文件本身找出来，而不是只找它所属税种的本体法：
`search_terms()` 用 `tax_terms.cited_documents()` 认出书名号里的标题，
`locate_cited_document()` 按 `tax_terms.title_candidates()` 给的由长到短的候选词
逐个查总局法规库，命中的第一条标 `_cited_target` 并直接取正文。本体法仍从 NPC
那一轮取回，当**其余法定依据**给结论定边界。四条规矩：

- **原文优先于解读**。解读件标题与原文件只差"的解读"三个字，字面命中率几乎并列，
  而解读按 ⑦ 不能当主依据。`locate_cited_document` 排序时把解读压到原文之后，
  只有原文一条都没取到，解读才排到首位。
- **只取到官方解读不等于取到了那份文件**。此时主依据仍由 `pick_primary` 按角色挑，
  程序另出
  `cited_note`（"点名的《……》只取到官方解读、没取到原文，答案要写明原文待核"），
  这句必须转写进答案；解读讲的是口径怎么执行，它进【执行口径与实务认定】照常参与
  论证，但不能顶替被它解读的那份文件，也不能不提原文缺失。
- **点名的文件层级通常低于其上位法**（多是规范性文件）。程序在这种情况下仍把
  它放主依据——用户问的就是这一份，拿《企业所得税法》顶上去等于没读那份公告；
  同时 `_why` 会写明"它的上位法在【其余法定依据】里并列给出，结论要与上位法同读"，
  这条必须照抄进答案。
- **点名文件的正文除了用来回答，还用来给上位规则作证**。取得原文正文后，
  `tax_answer.corroborate_validity_from_target` 读首段"根据……规定"列出的制定依据，
  给这些文件补时效证据（判据与限制见 `evidence_grading.md` 第 7 条）。企业重组这道题的
  实际效果：财税〔2009〕59 号、财税〔2014〕109 号从"进不了依据栏"回到【其余法定依据】，答案里连带
  证据来源那一句一起照抄。

`--answer` 走的是同一条链路，输出里给出主依据（含文号）、其余法定依据、执行口径与
实务认定、【适用边界】。

## 专业口径缺口：准则那一层不在 L1–L4 之内

**为什么要单列这一节**：税法条文常常不自己定义专业概念。企业所得税的条款讲
"计入当期损益""账面价值"，重组与抵债的条款讲"债务重组""企业合并"，优惠条款讲
"会计上确认的收入"——会计怎么处理写进了税法适用要件里，税上的结论就跟着会计的
认定走。除会计外，用户还会直接问审计、内控、评估、证券监管口径的原文（"审计准则
第XX号怎么说""内控应用指引对X的要求"），也会问证券交易所层面的自律规则（"深交所
上市规则/交易规则怎么说""减持、回购、信息披露的交易所规定原文"）。这些都不属于
税收规定，五个税收源一条都不收（各自的覆盖范围见 SKILL.md ⑪），L1→L4 走到头也取不到
"准则原文怎么说"这一层。这一层取不到，答案是拿训练数据里的旧准则记忆补出来的，正是
本项目最忌讳的那种答法。

**这一层分三个子技能，按要的东西选**：

- 要**规范逐条原文全文**（某准则/指引第 X 条到底怎么写的）→ `subskills/maodocs/`
  （纯标准库直连 docs.maoyanqing.com 静态站，覆盖企业/政府/小企业会计准则、注协审计准则、
  企业内控规范、资产评估准则、证监会监管规则适用指引五域，无 WAF、不调模型）。
- 要**实务答疑 / 监管处罚案例 / 某准则衍生哪些问答** → `subskills/chenyiwei-bbs/`
  （公开 REST，匿名访问，不调模型；它也能附带给企业准则原文，但取原文优先走 maodocs，
  静态、可复现、不吃第三方接口）。
- 要**证券交易场所自律规则、或某部门规章/规范性文件在交易所官网的原文定位** →
  `subskills/szse-lawrules/`（www.szse.cn/www/lawrules，先 `build` 建本地索引再离线
  `query`；法律/行政法规/司法解释/证监会规章·指引·规范性文件/废止公告走标准库直连，
  十二类"本所业务规则"走浏览器渲染，都不调模型）。

**什么时候用**：① 判型报出【会计口径缺口】就走这一层——`tax_answer.py` 的 `--plan`
与 `--answer` 都会打这一栏（词表在 `tax_analyze.ACCOUNTING_SIGNALS`，右边是"要先问清
会计的哪一件事"）。程序没认出来、但你正要引的那条税法条文里写着"会计上……""账面
价值""确认收入的时点"，同样是这个信号，照样去取。**审计/内控/评估/证券口径不由词表
自动触发**（词表只盯"税法借用会计结果"这一条路径），题面直接问某一专业规范原文时，
按题面判断走 maodocs；问证券交易所层面的自律规则（上市/交易/披露/回购/减持等）走
szse-lawrules。

**什么时候不用**：题目只问税率、期限、地点、单证这类与专业确认无关的规则。取准则
换不来任何税法结论；认错了多半是多一次检索，但别为了"答得看起来更全"顺手引准则。

**怎么用**：入口都在子技能文档里，主线不包一层脚本把它接进 ④/⑧。

chenyiwei-bbs 三条 curl：

```bash
# 1) 条文检索：从返回的 groups[].slug 里取 slug（不能按编号自己拼，见下面第二条硬规矩）
curl -s "https://bbs.auditdog.cn/api/learn/search?q=%E5%90%88%E5%B9%B6%E8%B4%A2%E5%8A%A1%E6%8A%A5%E8%A1%A8"
# 2) 整篇准则原文：units[].heading 就是"第二条 …"这样的条款号
curl -s "https://bbs.auditdog.cn/api/public/ref/cas-33"
# 3) 同一准则下的实务答疑：拿 tid 再换 detail 看完整问答
curl -s "https://bbs.auditdog.cn/api/public/ref-posts?slug=cas-33"
```

maodocs 两条命令（脚本在 `subskills/maodocs/maodocs.py`，纯标准库）：

```bash
# 1) 在某个分类里按关键词找条目：输出 results[].href / url
python subskills/maodocs/maodocs.py search cas "长期股权投资"   # 会计/审计/内控/评估/证券别名见 categories
# 2) 取逐条原文（含发文机关/日期/文号/正文）
python subskills/maodocs/maodocs.py fetch "https://docs.maoyanqing.com/accounting/ent/cas/02.html"
```

szse-lawrules 三条命令（脚本在 `subskills/szse-lawrules/szse.py`；先 `build` 建索引，之后离线 `query`）：

```bash
# 1) 建本地索引（默认只走标准库可枚举的七类通道，约 724 条；--snapshot 并入落地页快照）
python subskills/szse-lawrules/szse.py build --snapshot
# 2) 离线按关键词查，命中给"规则名+发布日期+原文链接+所属分类"
python subskills/szse-lawrules/szse.py query 回购 --limit 10
# 3) 取某一条原文（HTML 直连取正文；PDF/DOC 附件只回链接）
python subskills/szse-lawrules/szse.py fetch "http://www.szse.cn/lawrules/rule/trade/current/t20260424_620190.html"
# 需要"本所业务规则"（股票/债券/基金…）那一类时补浏览器渲染：python …szse.py build --browser --channel stock
```

## 优惠封闭枚举：这一层不是专业口径，是税收依据本体

上面三个子技能答的都是**专业口径**（会计/审计/证券），不进 ⑧ 定级。`subskills/tax-preference/`
与它们并排但性质不同：它给的是**税收优惠的权威封闭枚举**——《减免税政策代码目录》按
收入种类、政策大类、8 位减免性质代码列全现行有效 / 已失效优惠，附文号与优惠条款。五个
在线源按关键词召回单份文件，凑不出这个去重全集，所以"某税种/某主体名下有哪些优惠"
这一问只有它能答。

tax-preference 三条命令（脚本在 `subskills/tax-preference/preference.py`；同步复用
`scripts/tax_sync.py`，全程 plain HTTP、不调模型）：

```bash
# 1) 抓目录直链→比版本→变了才下载重建（--check 只报有无新版；--force 强制重下）
python subskills/tax-preference/preference.py sync
# 2) 离线查询：多词 AND；可按税种/大类/状态过滤，或按减免性质代码精确反查
python subskills/tax-preference/preference.py query 研发 加计 --type 企业所得税
python subskills/tax-preference/preference.py query --code 01010503
# 3) 列收入种类及条数，用于浏览某税种覆盖面
python subskills/tax-preference/preference.py list-types
```

**取到之后放哪**：目录条目就是税收依据本体，命中给出的**文号取回主线后照常进 ⑧ 位阶×时效
定级、可当主依据**——这与三个专业口径子技能相反。**但两条边界要守住**：① 目录是双栏结构，
`有效` 栏根本不录日期（实测 912 条有效期起/止全空），条目在不在效由它所在栏决定，**不能拿
"有效期止为空"当"永不过期"**、也不能指望从有效条目读出到期日；要到期日就按文号回五源取
正文，`tax_evidence.expiry_of` 从公告自载的"执行至／延续至／自…至…"那句里取止日、
`period_start_of` 从"自…至…"的成对写法里取起日，取到
了才谈到期（详见 `evidence_grading.md`「时效判定八条」第 8 条）；② 目录只到"优惠项目名＋代码
＋文号＋条款"这一层，正文、施行/废止日期、解读一律回五源取。`[失效]` 条目仅用于补充/更正
申报历史业务。

**什么时候不用**：题目问的是税率、扣除比例、时限这类单点规定，五源精检更快更全；本技能
擅长的是"列全"和"按代码反查"，不是取代主线检索。

**取到之后放哪**：准则原文与实务答疑都**不是税收法定依据**，不进 ⑧ 的层级表，
也不与税法条文并列。它们只占两个位置——【适用边界】里当前提
（"本结论假定会计上按 X 确认；会计口径变了结论要重算"），或【执行口径与实务认定】
栏，写"规范名＋条款号"并标明它不是税收法定依据。

**两条硬规矩**：

- **接口/标题里的 `docNo`、URL 里的 t 编号不能当版次用**。实测 chenyiwei `/api/public/ref/cas-33` 报
  `docNo=财会〔2006〕3号`、`doc.officialUrl` 指向 2008 年的页面，而第二条正文已经是
  "拥有对被投资方的权力"并出现"结构化主体"——那是 2014 年修订后的措辞；maodocs
  `cas/02.html` 标题带"（财会〔2014〕14号）"、正文是修订后文本，同分类 `cas/01.html`
  却仍标"（财会〔2006〕3号）"；szse `…/t20250327_612564.html` 标题写"（2023年修订）"、
  列表日期 2023-12-15，而 URL 的 t20250327 只是站方 CMS 生成序号。文号与序号都是录入项、
  不跟修订走，写出处只写规范名与条款号，版本另找证据。
- **`status` /"现行有效"标注不能替时效判定**。chenyiwei 取到的准则条目 `status` 全是
  `current`、`supersededBy` 全是 `null`，分不出版次；maodocs 详情页写着"时效性：现行
  有效"是站方文字标注、无修订链。`tax_evidence.judge_validity` 都不接管，也别在答案里
  写"该准则现行有效，依据接口/页面判定"。

这两条硬规矩只有文档、没有代码断言，这是取舍不是遗漏：主线不取准则正文进答案层
（不走 ④、不进 ⑧ 打分），没有任何一条代码路径能替把这道关。要把它做成可执行的闸，
先得有"包装脚本 + 准则内容进定级"这条链，而那条链正是"怎么用"一段拒绝掉的——准则
内容一旦进了定级表，就会被当作税收依据来打分。

chenyiwei 的其余接口差异（`recent?days=1` 可以整天空、`penalties` 的分页字段是字符串、
`slug` 命名不带统一年份后缀）记在 `subskills/chenyiwei-bbs/NOTE.md`，那份文件与上游字节
一致，改动都只写在 NOTE.md 里；maodocs 的站内实测差异（索引页混挂全局导航、小企业准则
不按主题分篇、Git Bash 路径改写）记在 `subskills/maodocs/NOTE.md`；szse 的站内实测差异
（业务规则页运行时模板需浏览器、规范性文件多为 PDF/DOC 附件、偶发 502 重试、t 编号不表
版次）记在 `subskills/szse-lawrules/NOTE.md`。

## 立法过程文件：草案那一层也不在 L1–L4 之内

**为什么要单列这一节**：用户会问还没表决通过的文本。实测原题是"国务院常务会议审议
并原则通过新版《税收征管法》修订草案，决定将草案提请全国人大常委会审议，请解读修订
草案"。照原话去取，五个源交回的是《中华人民共和国税收征收管理法》现行有效版本
（法律那一档、现行有效），命令行与界面都不报错、也不空——把旧法的条文当成草案的修改点写进
答案，比不答更像答错了。

**判据只看题面用词，不看检索结果**：结果层分不出"库里没有这份文件"与"这一档根本不
在库的收录范围"，而这一区别必须说出口。三档词表在 `tax_analyze.LEGISLATIVE_STAGES`
（征求意见、草案/修订稿/送审稿、提请审议/常务会议通过），`tax_analyze.legislative_stage`
在 ① 把它登记进计划，`tax_analyze.legislative_note` 写成整句。命令行
（`tax_analyze.py` 的面板与 `tax_answer.py` 的 `--plan`/`--answer`，后者经
`tax_answer._print_legislative_note`）与界面（`tax_server` 的 `legislative_note` 字段，
前端渲染成"收录范围"一栏）共用这一句，不在两处各说各话。界面那一栏按用户原话判，
不按被换成本体法名之后用来检索的 keyword 判——换了名"草案"两个字就没了。

**取到之后放哪**：草案文本不在五源里，⑧ 的位阶表也没有它的位置。走出库取证时，
检索轮次会自动改道（见 `commands.md` 与 SKILL.md ③ 的分轮编排）：第 1、2 轮取回的
同名现行版本一律重标为"修订基线"，追加的一轮去三个实位取草案解读——人大网站内
（`legis` 源，`so360_search site:npc.gov.cn`）+ 税屋 + 公众号（草案逐条解读文章只在
这两个实务源里）。这三源取回的条目都带 `legislative_process` 或 `medium`/`low` 标记，
`pick_primary` 把它与 `low` 一样永久排除在主依据之外，即使它是唯一召回项。答案要标明
那是报道转述、不是库内依据；不能用草案条款论证当期义务成立，因为文本还没表决。
拿同名现行版本顶替它，按 ⑦ 属于答非所问。

**什么时候这一栏是空的**：问的是已公布文本。评测集 1001 题里这三档词一题都不出现
（公开题库只考已生效的规则），所以它盯的是用户原话；盯住它的是
`tests/test_routing_terms.py::test_legislative_stage_flags_draft_wording`，反向用例是
`test_legislative_stage_is_silent_for_promulgated_texts`。立法取证轮覆盖三个源、且用
草案词而非主题短词，由 `tests/test_source_defects.py::test_draft_round_also_searches_shui5_and_wechat`
与 `test_draft_round_uses_draft_term_not_short_term` 钉住。
